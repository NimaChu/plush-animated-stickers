# 从用户描述设计角色

本入口适用于没有现成形象图、希望先创作角色再制作表情的请求。图像创作由宿主图像生成工具完成，合成脚本不把文字直接转换成图像。不需要原 Sticker 项目或历史角色素材。

## 将描述整理为设计简报

原样保存用户描述为工作区的 `brief.txt`，区分用户明确要求与助手补齐的设计假设：

- 主体类型、体型/头身比、轮廓和主要颜色。
- 眼鼻口、耳角尾、花纹等能够跨动作保持的辨识特征。
- 材质、性格气质、原有或明确要求的配件。
- 需要全身、半身还是头部，表情使用场景；未指定时可用简洁正面全身基准与日常聊天动作作为制作假设。

例如“奶黄色小猫，圆脑袋短腿，傲娇但心软，做成绒毛玩偶表情”，已经足以创作首张基准图。可补足柔和光线、完整四肢和留白；不要凭空增加服装、标语、故事道具或品牌。描述宽泛时可给出一个合理初稿，无需把所有美术选择变成问卷。只在影响身份或用户明确要求的关键冲突上澄清。

## 生成角色基准图

使用 [角色基准图提示词](prompts.md#文字描述生成角色基准图)，完整填入简报。输出单个角色、清楚的中性或轻微友好表情、适合看清轮廓的正面构图，保持用户的造型与配件要求；全身图需要耳朵、四肢、尾巴等实际存在的部位完整入画。此处不生成动画格子或写上字幕。

对全新文字设计使用图像生成工具的“无参考新建”入口。使用内置 `image_gen` 时不传 `referenced_image_paths` 或 `num_last_images_to_include`，避免把对话里其他图片意外当作身份；如果用户明确提供参考，则走带参考的设计/编辑流程。透明设计请求传真实透明背景参数；非透明基准图也能用于锁定身份，后续动画格子仍需真实 alpha。

将工具返回原图复制为本次新目录下的 `reference/character-v1.png`（保留实际格式，不只改扩展名），保存工具输出原件、完整设计提示词、实际参数和生成记录。先检查可解码、尺寸和非空图像，再实际查看设计是否覆盖用户描述。主观设计效果不做自动打分关卡；生成失败或无法查看时如实报告，不能用提示词替代真实形象图。

用户要求多方案时，分别保存候选并按其选择推进；没有这个要求时不强制生成多套。需要修改时在新的版本路径迭代，不覆盖旧图。

## 将形象固定为后续身份依据

记录 `identity.json`，包含：原始描述路径、助手假设、基准图路径/SHA-256、工具/设计提示词记录路径、实际观察到的比例和五官标记、当前设计版本及用户查看状态。

用户授权整套创作且未要求先选稿时，首张基准图作为本次**暂定身份参考**，展示并保存后继续；状态仍为 pending-user-review。用户要求先确认形象时，先交付可查看的基准图，再等待选择，不先生成其衍生表情。只有用户实际采纳才标记 accepted；既有项目的批准参考区按项目规则使用，未采纳设计继续保存在 `work/`。

后续每个动作、横幅、封面、图标都传入同一份实际基准图，并使用从它提取的身份块，不能每个动作重新仅凭描述设计角色。不要把上一动作的生成结果层层当新身份来源；有补充视图需求时以同一基准制作并记录用途。设计基准发生变更时，明确关联受影响的衍生素材，避免混入两个版本的角色。

在 GIF 构建配置的 `provenance` 中列入 `brief.txt`、基准图、`identity.json`、设计及动作提示词和生成记录。这样交付包脱离原工作目录后仍保留“描述 → 形象 → 动作”的来源链；这些文件应真实存在，路径相对配置文件解析。
